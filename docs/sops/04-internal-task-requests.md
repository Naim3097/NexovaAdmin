# SOP 4 — Internal Task Requests

**Owner:** everyone · **Board:** nexops.my/tasks (Sprint Tasks)

The playbook rule "production requests flow through Danisy" becomes: **requests
flow through Sprint Tasks, triaged by Danisy**. Danisy is the control point, not
the queue.

## Which board?

- Work that belongs to a client project's pipeline (kickoff, strategy,
  production, QC, live) → it's a **project stage**, lives on the project.
- Everything else — one-off asks, internal work, "can someone…" — → **Sprint Task**.
  If you'd otherwise WhatsApp Danisy, it's a Sprint Task.

## Steps

1. Create the task on /tasks — title, details, **PIC**, deadline. Default
   deadline is **3 days** if nothing is agreed. You can also brain-dump a batch:
   paste the raw list and the AI parses tasks + PICs.
2. Danisy triages daily: re-routes wrong PICs, merges duplicates, kills anything
   that's actually a project stage.
3. The deadline bot pings Telegram daily for tasks due tomorrow, and pings
   project stages due tomorrow/today with the PIC named. Nobody chases by memory.
4. PIC marks the task done on the board — not in chat.

## Rules

- A request that isn't on the board doesn't exist. WhatsApp is for conversation,
  the board is for commitments.
- No task without a PIC and a deadline. One name, one date.
